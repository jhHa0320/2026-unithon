# 작업일지 — 코레일톡(코레일) 앱 지원 확장

- 작성일: 2026-08-26
- 브랜치: `feature/korail-support` (사용자 요청으로 main이 아닌 별도 브랜치에서 진행)
- 선행 작업: `41aa9ec` feat: support KakaoTaxi — 이 커밋이 만든 멀티앱 패턴을 그대로 확장했다.
  배경은 `docs/worklog/2026-08-26-handoff-voice-multiapp-ui.md` §2-8 참고.

## 1. 목표

카카오톡·카카오택시에서 동작이 확인된 음성 자동화 파이프라인("안녕 손자" → 요청 발화 →
앱 실행 → 화면 읽기 → LLM 판단 → 클릭 반복)을 코레일톡에서도 쓸 수 있게 한다.
예: "부산 가는 KTX 예매해줘".

## 2. 패키지명 확인

실기기(R3CWA0J3J8Z)에 실제 설치된 앱을 `adb shell pm list packages | grep korail`로 확인:
**`com.korail.talk`** (코레일톡). 기획 문서에는 "코레일+"로 적혀 있으나 이 폰에 설치된 앱은
코레일톡이므로 이 패키지를 대상으로 한다.

## 3. 수정 내역 (카카오택시 때와 동일한 4곳 패턴)

1. `res/xml/test_accessibility_service_config.xml` — `android:packageNames`에 `com.korail.talk`
   추가. **이게 핵심** — 이 목록 밖 앱은 OS가 접근성 이벤트 자체를 안 보내준다. 주석도 갱신
   (기존 주석이 "코레일은 결제가 실행되니 제외한다"였는데, 이제 의도적으로 포함하므로
   "취소 가능한 구간까지만 테스트" 경고로 교체).
2. `AndroidManifest.xml` — `<queries>`에 `com.korail.talk` 추가 (targetSdk 37 패키지 가시성,
   없으면 `getLaunchIntentForPackage`가 null 반환).
3. `WakeAndLaunchActivity.kt` — `resolveTargetPackage()`에 코레일 분기 추가.
   키워드: 기차/열차/코레일/ktx/케이티엑스/승차권/무궁화호/새마을호 (소문자 비교).
   STT가 "KTX"를 "케이티엑스"로 받아쓰는 경우가 있어 둘 다 넣었다.
   "택시" 검사를 먼저 하는 기존 순서 유지 — "기차역까지 택시 불러줘"에서 택시가 이겨야 한다.
4. `TestAccessibilityService.kt` — `TARGET_PACKAGES`에 `com.korail.talk` 추가.

백엔드는 **수정 없음** — 프롬프트(v3)는 v2에서 이미 도메인 중립으로 바뀌었고
(KTX 전용 슬롯명 제거가 오히려 v2 작업이었다), `app_package`는 실제 이벤트 패키지를
그대로 전송하는 구조라 코레일톡이어도 추가 코드가 필요 없다.

## 4. 알려진 위험 / 미검증

- **코레일톡은 실제 결제가 실행되는 앱이다.** 프롬프트 규칙 5("전송·결제·확정도 정상 진행")에
  따라 결제 버튼도 자동 클릭된다. 리허설은 반드시 취소 가능한 구간까지만 하거나,
  결제 직전에 수동 개입할 준비를 하고 할 것 (KTX는 출발 전 취소 시 수수료 환불 가능하지만
  손해가 0은 아니다).
- **실기기 엔드투엔드 미검증** — 빌드/설치까지만 확인. 코레일톡 화면(역 선택 캘린더,
  좌석 선택 그리드 등)에서 LLM이 잘 판단하는지, 접근성 라벨 없는 커스텀 뷰가 없는지는
  실기기 테스트로 확인해야 한다. 문제가 보이면 `services/prompt.py` 튜닝(PROMPT_VERSION 올릴 것).
- 코레일톡 메인 화면에 팝업/공지가 자주 뜬다 — 카카오택시 때처럼 "팝업 닫기"를 LLM이
  스스로 판단해야 하는데 미실측.

## 5. 실기기 테스트 1차 결과와 수정 — "바로 예매"가 안 눌리는 문제

첫 실기기 테스트("부산역 가는 열차 예매해줘"): 시간대 되묻기 → 열차 선택까지는 됐지만
**바로 예매 버튼을 못 누르고** ASK_USER만 6연속 나오다가 클라이언트의
`MAX_CONSECUTIVE_ASK_USER`(5) 초과로 중단됐다.

**로그로 확인된 증상** (`adb logcat` + `/tmp/uvicorn.log` 대조):
같은 열차 행(ITX-새마을1001, id=1)을 confidence 0.95로 **7번 반복 클릭** →
이름 없는 View(id=48)를 찍어서 클릭 → 그 뒤 화면에서 ASK_USER 반복 → 중단.

**근본 원인**: 코레일톡은 Compose 앱인데, 열차 행을 탭하면 뜨는 바텀시트의
"좌석 선택"/"바로 예매" 버튼이 **라벨 없는 clickable View + 그 안의 클릭 불가 TextView(라벨)**
구조다(uiautomator 덤프로 실측). 우리 컨텍스트 빌더는 노드 자체의 text/desc만 보내므로
LLM에게는 "이름 없는 클릭 가능 View"들만 보였고, 어느 게 바로 예매인지 알 수 없어
라벨이 있는 열차 행만 계속 클릭한 것.

**수정**: `TestAccessibilityService`에 `synthesizeLabel()` 추가 — 자체 라벨이 없는 clickable
노드는 자손 노드의 text/desc를 모아(최대 3조각·60자) content_description으로 합성해서 보낸다.

**검증**: 실제 바텀시트 uiautomator 덤프를 새 로직대로 ElementDTO로 변환해 실서버
`/decide`(Gemini)에 보내는 시뮬레이션(`simulate_decide.py`)으로 확인 —
수정 전에는 라벨 없던 요소들이 전부 '좌석 선택'/'바로 예매'/'운행 정보' 라벨을 갖게 되고,
LLM이 **'바로 예매'(id=47)를 confidence 0.95로 정확히 선택**했다
(instruction: "…바로 예매 버튼(47번)을 눌러 예매를 진행한다").

## 6. 중단(스톱) 기능 + "계속 입력 대기" 버그 수정

사용자 요청 3건: ① 음성 중단 명령이 실제로 중단되게, ② 화면에 중단 버튼, ③ 스톱 시
진행 중이던 명령 종료. 조사 중 ②의 배경 증상("계속 사용자 입력을 대기하는 것 같다")의
원인을 확인했다.

**확인된 버그 — 세션 종료 후 무한 재질문**: `onAccessibilityEvent`가
`!isSessionActive || packageChanged`이면 무조건 새 세션을 시작했다. 즉 DONE/중단 후에도
사용자가 대상 앱 화면에 있는 한 다음 접근성 이벤트가 오자마자 "무엇을 도와드릴까요?"를
다시 TTS로 묻고 마이크를 여는 동작이 무한 반복됐다. 이게 "계속 입력을 대기한다"는 증상의 정체.

**수정 내역**:
- `TestAccessibilityService.sessionRequested` (static flag) 추가 — `WakeAndLaunchActivity`가
  세워줄 때만 새 세션 시작. 완료/중단 후 앱에 남아 있어도 다시 묻지 않는다.
  (adb 테스트 트리거 `WakeTriggerReceiver`도 같은 Activity를 거치므로 그대로 동작.)
- `StatusOverlayManager`에 "그만하기" 버튼 추가. 기존 오버레이는 `FLAG_NOT_TOUCHABLE`이라
  터치 자체가 불가능했음 — `FLAG_NOT_FOCUSABLE`만 남겨 버튼 영역 터치만 받게 변경.
  종료 안내(완료/중단/실패)는 버튼 없이 5초 보여주고 오버레이가 스스로 사라진다
  (기존엔 "완료: …"가 영영 떠 있었음).
- `stopSession()` — 버튼과 음성 중단 명령의 공통 경로: 예약된 화면 스캔 취소, 마이크/TTS 정지,
  `pendingGoal`/`sessionRequested` 클리어, "네, 중단했어요" 안내.
- **날아가 있던 서버 응답 무효화**: `sessionEpoch` 세대 번호를 두고, 응답 도착 시 요청 시점과
  epoch가 다르면 버린다 — 중단을 눌렀는데 3초짜리 LLM 응답이 뒤늦게 도착해 클릭을
  실행해버리는 레이스 방지.
- 음성 중단 명령: ASK_USER 답변·목표 답변에서 "취소/그만/중단/멈춰/스톱/하지마/종료" 키워드
  (공백 제거 후 부분 일치)면 서버 왕복 없이 즉시 `stopSession()`. CLAUDE.md §5-1은 "아니 취소해줘"를
  user_speech로 보내는 예로 들지만, 중단만큼은 왕복 사이에 클릭이 나가면 안 되므로 클라이언트가
  바로 처리하는 걸로 결정(사용자 요청). "아니/아니요" 같은 단순 부정은 기존대로 user_speech로 간다.
