**PRD — AI 디지털 가이드 레이어**

어르신·디지털 취약계층의 “앱 사용법을 알아내는 일”을 없애는 Android 접근성 서비스

UNWORK Hackathon · 2026.08

# **개요**
## **한 줄 정의**

|**한 줄 정의**<br>사용자가 “무엇을 하고 싶은지”만 말하면, AI가 현재 앱 화면의 UI를 이해해 다음에 눌러야 할 요소를 화면 위에서 바로 안내하는 Android AI 가이드 레이어.|
| :- |

## **제품 목표**
- 사용자가 앱 메뉴 구조를 외우거나 매뉴얼을 검색하지 않아도 목적을 달성하게 한다.
- 자녀·보호자가 부모님의 반복적인 “어디 눌러?” 질문에 대응하는 시간을 줄인다.
- AI가 사용자를 대신해 임의로 조작하지 않고, 최종 판단과 실제 클릭은 사용자에게 남긴다.
- 기존 앱을 수정하지 않아도 Android 접근성 레이어 위에서 동작하는 MVP를 만든다.
- 해커톤에서는 카카오톡 등 1개 앱의 2~3개 대표 시나리오에서 end-to-end 안내 성공을 목표로 한다.
## **배경**
스마트폰 서비스는 빠르게 고도화되지만 앱마다 메뉴 구조·아이콘·용어가 다르다. 디지털 사용에 익숙하지 않은 고령자는 원하는 기능 자체를 몰라서가 아니라 “어디에 있는지”, “어떤 메뉴를 거쳐야 하는지”를 찾는 과정에서 막히는 경우가 많다. 이때 기존 해결책은 매뉴얼, FAQ, 콜센터, 자녀의 원격 설명처럼 사용자가 다시 UI를 해석하도록 요구한다.

UNWORK 관점에서 지워야 할 것은 클릭 자체가 아니라, 클릭 전에 발생하는 메뉴 탐색·설명서 검색·반복 질문·기억 부담이다. 사람에게 남길 것은 목적, 선택, 책임이다.

# **문제 및 해결 방안**
## **사용자 문제**
- 원하는 기능이 있어도 메뉴 위치와 용어를 몰라 다음 단계로 넘어가지 못한다.
- 앱 업데이트로 UI가 바뀌면 이전에 배운 사용법이 무효화된다.
- 스마트 ARS·FAQ·튜토리얼은 현재 화면과 설명을 사용자가 직접 대조해야 한다.
- 부모는 자녀에게 반복적으로 묻고, 자녀는 같은 설명을 반복하면서 시간·감정 소모가 발생한다.
- 은행·결제처럼 민감한 기능을 AI에게 완전 위임하는 것은 보안·신뢰 측면에서 부담스럽다.
## **해결 방안**
1. 사용자가 자연어 또는 음성으로 목적을 말한다. 예: “카톡에서 차단한 친구 다시 풀고 싶어.”
1. AccessibilityService가 현재 화면의 UI text, contentDescription, 클릭 가능 여부, 화면 좌표 등을 읽는다.
1. AI 에이전트가 사용자 목표와 현재 UI 목록을 보고 “다음에 선택해야 할 UI 요소” 하나를 결정한다.
1. 해당 요소의 실제 좌표 위에 테두리·화살표·짧은 설명을 오버레이로 표시한다.
1. 사용자가 직접 클릭한다. 화면이 바뀌면 AccessibilityEvent를 감지해 동일 과정을 반복한다.
1. 민감한 판단·인증·송금·결제는 자동 실행하지 않고 사용자에게 명확히 남긴다.

# **타겟 및 시나리오**
## **타겟 사용자**
- Primary: 스마트폰 앱 메뉴 탐색에 어려움을 느끼는 60대 이상 사용자.
- Secondary: 부모에게 스마트폰 사용법을 반복적으로 설명하는 자녀·보호자.
- 확장 타겟: 디지털 초보자, 인지·학습상의 어려움이 있는 사용자, 한국어 UI가 익숙하지 않은 사용자.
- MVP 타겟 환경: Android 실기기 + 카카오톡 등 일반 생활 앱 1~2개.
## **사용자 시나리오**
대표 시나리오 A — 카카오톡 채팅방 알림 끄기

1. 사용자가 카카오톡을 연 상태에서 “이 채팅방 알림 끄고 싶어”라고 말한다.
1. AI 가이드가 현재 화면에서 메뉴/더보기 요소를 찾고 해당 위치를 강조한다.
1. 사용자가 직접 누른다.
1. 새 화면을 다시 읽고 “알림 끄기” 또는 관련 설정을 강조한다.
1. 설정 완료 후 “완료됐어요”라고 알려준다.

대표 시나리오 B — 차단 친구 해제

같은 방식으로 친구/설정/차단친구 관리 등 다음 단계만 순차 안내한다. 사용자가 화면을 외우거나 검색하지 않아도 된다.

**[S2] Gemini Live - Android Help**\
https://support.google.com/gemini/answer/15274899\
Android에서 화면 공유를 켜고 다른 앱을 사용하면서 Live 대화를 계속할 수 있음. 화면에 대한 실시간 도움을 제공.

**[S3] 손주도움 - Google Play**\
https://play.google.com/store/apps/details?id=com.guideops.app\
스마트폰 화면·키오스크·약봉투 등을 카메라로 비추면 다음 버튼과 사용법을 음성 안내.

**[S4] Android AccessibilityService API**\
https://developer.android.com/reference/android/accessibilityservice/AccessibilityService\
접근성 서비스는 UI 이벤트를 받고 활성 창의 UI 트리를 조회할 수 있으며 접근성 오버레이를 그릴 수 있음.

**[S5] Android AccessibilityNodeInfo API**\
https://developer.android.com/reference/android/view/accessibility/AccessibilityNodeInfo\
UI 노드의 text, contentDescription, boundsInScreen 등 접근성 정보를 조회할 수 있음.

**[S6] Google Play AccessibilityService 정책**\
https://support.google.com/googleplay/android-developer/answer/10964491?hl=ko\
접근성 API 사용 시 선언·공개·동의 요구. 일반 앱의 자율적 계획·실행 자동화는 제한되며 장애 지원이 핵심인 접근성 도구는 별도 기준 적용.

**[S7] Google Play 민감 권한/API 정책**\
https://support.google.com/googleplay/android-developer/answer/16558241\
Accessibility API는 보안 통제 우회·기만적 UI 조작 등에 사용할 수 없고 목적에 필요한 최소 데이터만 처리해야 함.
