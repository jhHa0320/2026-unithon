# PRD — 화면 Off 음성 자동예매 에이전트

어르신·디지털 취약계층이 "앱을 찾아 열고 조작하는 일" 자체를 없애는 Android 음성 자동화 서비스

UNWORK Hackathon · 2026.08

# 개요

## 한 줄 정의

| **한 줄 정의** 화면이 꺼진 상태에서 사용자가 음성으로 목적을 말하면, AI가 대상 앱을 스스로 실행해 목적지·시간·좌석까지 자동으로 진행시키고, 결제까지 가능하게 하는 레이어. |
| --- |

## 제품 목표

사용자가 앱을 직접 찾아 열고 메뉴를 조작하는 선행 작업(화면 On, 앱 탐색, 단계별 입력)을 전부 없앤다.

자녀·보호자가 예매를 대신 해주거나 반복 설명하는 시간을 없앤다.

AI는 목적지·시간·좌석 선택까지 스스로 진행하되, 실제 금전이 소요되는 결제 실행만은 사용자에게 남긴다.

기존 앱을 수정하지 않아도 Android 접근성 레이어 위에서 동작하는 MVP를 만든다.

해커톤에서는 코레일+ 앱의 KTX 예매 시나리오 1개에서 화면 Off 음성 호출→결제 도달까지 end-to-end 성공을 목표로 한다.

## 배경

기존 '말하면 척척'(fluiz 기반, 서울AI재단 공동개발)은 음성 제어를 지원하지만 사용자가 앱을 직접 찾아 열고 서비스를 실행해야 하는 선행 UX Work가 남아있다. 이 프로젝트는 이 선행 작업 자체를 제거하는 데 집중한다: 화면이 꺼진 상태에서도 음성 한마디로 목적이 실행 단계까지 진입하게 한다.

UNWORK 관점에서 지워야 할 것은 화면을 켜고 앱을 찾고 메뉴를 눌러가는 조작 노동이다. 사람에게 남길 것은 "이 결제를 실행할지"에 대한 최종 판단이다.

[도식 1] 사람이 해야 할 판단(결제 실행)은 남기고 그 외 전 과정을 자동화

# 문제 및 해결 방안

## 사용자 문제

화면을 켜고, 잠금을 풀고, 앱을 찾아 열고, 메뉴를 눌러야 예매가 시작된다.

목적지·시간·좌석 단계를 사용자가 매번 직접 입력/선택해야 한다.

명절 등 예매 경쟁 시간대에는 몇 초의 지연도 좌석 확보 실패로 이어진다.

고령자는 앱을 여는 것부터 막혀 자녀에게 예매를 부탁하는 경우가 많고, 자녀는 같은 예매를 반복 대행하며 시간·감정 소모가 발생한다.

## 해결 방안

화면 Off 상태에서도 사용자가 wake word 뒤 목적을 말한다. 예: "내일 아침 서울에서 부산 가는 KTX 예매해줘."

서비스가 코레일+ 앱을 자동 실행한다.

AccessibilityService가 현재 화면의 UI text, contentDescription, 클릭 가능 여부, 화면 좌표 등을 읽는다.

AI 에이전트가 사용자 목표와 현재 UI 목록을 보고 다음에 실행할 UI 요소를 판단해 performAction(ACTION_CLICK) 또는 setText로 직접 실행한다.

목적지·날짜·시간·좌석 선택까지 완료되면 결제까지 진행한다.

사용자가 이 화면에서 직접 결제를 눌러야만 실제 결제가 진행된다. AI는 결제 버튼을 대신 누르지 않는다.

[도식 2] 화면 Off 음성 호출부터 결제 자동 진행

## 차별점

| **기준** | **기존 방식** | **우리 제품** |
| --- | --- | --- |
| 행동 주체 | 사용자가 화면을 켜고 앱을 열어 직접 조작 | 화면 Off 음성 호출만으로 목적지~좌석까지 AI가 자동 진행 |
| 핵심 가치 | 대화형 도움 또는 부분적 음성 제어 | 앱 탐색·조작 노동 자체를 제거 |
| 화면 이해 | 화면 공유·카메라 또는 사용자 직접 조작 | Accessibility UI Tree 우선, Vision은 보조 |
| 안전 철학 | 전 과정 AI 위임 | 좌석까지 자동, 결제 실행만 인간에게 남김 |
| UX | 앱을 열고 단계별로 조작 | 화면 Off 음성 한마디 → 결제 대기 화면까지 자동 도달 |

## 결제·예매 연동 범위 (In-Scope / Out-of-Scope)

이번 해커톤 스코프에서는 실제 결제망에 연결하지 않는다. 목표는 "화면 Off 음성 호출 → 자동 진행 → 결제 대기 확인 → 사용자 확인"이 실제 서비스처럼 자연스럽게 이어지는 UX를 보여주는 것이며, 결제·예매 확정 자체는 데모용 더미(Mockup) 화면으로 대체한다.

| **구분** | **범위** |
| --- | --- |
| In-Scope | 우리 앱에 사전 등록해 둔 결제수단(Mock)이 기차 예매 앱과 연동되어 예매·결제가 완료되는 것처럼 보이는 UI/UX 데모 플로우. 결제 대기 확인 화면 → 사용자 확인 탭 → (Mock) 결제수단 연동/완료 화면까지의 시연용 화면 전환. |
| Out-of-Scope | 실제 PG사 결제 승인/취소 연동. 코레일·SRT 등 외부 플랫폼과의 Real-time API 결제 확정. 이 범위에서는 실제 금전 이동이나 실제 예매 확정이 발생하지 않는다. |

Mock 화면은 코레일+ 앱의 실제 결제 화면을 자동 조작해 만들지 않고, 우리 앱 자체 오버레이에서 독립적으로 렌더링한다. 사용자가 결제 대기 화면에서 직접 확인해야만 다음 화면으로 넘어간다는 human-in-the-loop 원칙은 Mock 단계에서도 동일하게 유지한다.

# 타겟 및 시나리오

## 타겟 사용자

Primary: 예매 경쟁이 치열한 시간대 이용자, 앱 조작 자체가 부담스러운 60대 이상 사용자.

Secondary: 부모의 예매를 대신 해주던 자녀·보호자.

확장 타겟: 디지털 초보자, 인지·학습상의 어려움이 있는 사용자, 반복 조작이 번거로운 일반 사용자.

MVP 타겟 환경: Android 실기기 + 코레일+ 앱.

## 사용자 시나리오

대표 시나리오 — 서울→부산 KTX 예매

사용자가 화면이 꺼진 상태에서 "내일 아침 서울에서 부산 가는 KTX 예매해줘"라고 말한다.

서비스가 코레일+ 앱을 실행하고 출발역/도착역/날짜를 자동 입력한다.

열차 목록에서 조건에 맞는 열차를 자동 선택한다.

좌석 등급/좌석을 자동 선택한다.

결제 대기 확인 화면이 뜨고 "총 OO원, 결제를 진행할까요?"를 사용자에게 확인받는다.

사용자가 결제 대기 확인 화면에서 확인을 누르면, 우리 앱에 사전 등록해 둔 결제수단(Mock)으로 예매 앱과 연동되어 결제가 처리되는 화면이 이어지고, 잠시 후 "예매가 완료되었습니다" 더미 완료 화면이 표시된다.

이 결제수단 연동·완료 화면은 시연용 Mockup이며, 실제 PG 승인이나 코레일 서버로의 결제 확정 요청은 발생하지 않는다.

# 성공·위험 요소

## 핵심 지표

| **지표** | **정의** | **MVP 목표** |
| --- | --- | --- |
| Task Success Rate | 화면 Off 호출부터 결제 대기 화면까지 중단 없이 도달한 비율 | 80%+ |
| Next-Step Accuracy | AI가 선택한 다음 UI가 실제 올바른 경로였던 비율 | 90%+ |
| Time to Wake | Wake word 인식부터 앱 실행까지 걸리는 시간 | 2초 이내 |
| Time to Payment Gate | 목적 발화부터 결제 대기 화면 도달까지 걸리는 시간 | 30초 이내 |
| Payment Control | 결제 버튼을 AI가 대신 누르지 않고 사용자 직접 실행을 유지한 비율 | 100% |

## 리스크

| **리스크** | **왜 발생하는가** | **대응** |
| --- | --- | --- |
| 매크로 탐지 | 코레일은 반복 조회·자동 입력 패턴을 상시 모니터링하며 의심 계정을 이용 정지시킴 | 데모는 자체 제작 목업 화면 우선 사용, 실 서버 호출 최소화 |
| Play 정책 위반 | Accessibility API로 예매 앱의 여러 단계를 자율 실행하는 것은 Play의 "자율적 계획·실행 자동화 제한" 조항에 저촉될 소지가 있음 | 결제 실행만은 반드시 사용자 확인을 거치도록 서버 규칙으로 하드코딩, 정책 심사 시 접근성 목적 소명 |
| 좌석맵 접근성 정보 부족 | 좌석맵이 canvas/이미지 기반이면 텍스트 노드가 없을 수 있음 | Screenshot + Vision fallback, 좌석 등급 리스트 화면으로 대체 |
| 화면 Off 음성 상시 감지의 배터리/OS 제약 | Doze 모드·제조사 백그라운드 정책으로 서비스가 죽을 수 있음 | 배터리 최적화 예외 등록 안내, Foreground Service 유지 |
| AI 오판으로 잘못된 열차/좌석 예약 | 목표 해석과 UI 의미 연결 오류 | 낮은 확신이면 진행 중단 후 사용자에게 확인 요청 |
| 결제 대기 화면 오조작 | 사용자가 무심코 결제를 누를 가능성 | 결제 대기 화면에 금액·경로·시간을 명확히 표시, 별도 확인 탭 요구 |
| 데모용 Mock 결제 완료 화면을 실제 결제로 오인 | 목업 화면을 실제 서비스처럼 정교하게 만들 예정 | 시연 시 목업임을 명확히 코멘터리로 고지, 화면 내 "Demo/테스트" 표기 병행 |

| 플랫폼 | Android Mobile |

**[S7] Google Play 민감 권한/API 정책**
