**제품설명서 — AI 디지털 가이드**

팀원이 10분 안에 제품의 문제·경험·범위를 이해하기 위한 설명서

UNWORK Hackathon · 2026.08

# **1. 우리가 만드는 것은 무엇인가**

|**제품 정의**<br>다른 앱을 대신 쓰는 AI가 아니라, 사용자가 보고 있는 앱 위에 “다음에 어디를 눌러야 하는지”를 직접 표시해 주는 Android AI 사용성 레이어다.|
| :- |

모바일 앱을 처음 쓰는 사용자는 “무슨 기능을 원하는지”는 알고 있어도 그 기능이 어디 있는지 찾는 과정에서 막힌다. 예를 들어 “카톡 채팅방 알림을 끄고 싶다”는 목적은 명확하지만 더보기 메뉴, 설정 위치, 용어를 알아야 한다. 우리 제품은 이 중간 단계를 AI가 맡는다.

![](Aspose.Words.399edf93-3576-47b2-9126-57c11cff011f.001.png)

[제품 개념] AI는 화면을 해석하고, 사용자는 실제 행동과 판단을 맡는다.
# **2. 왜 필요한가**
- 앱마다 메뉴 구조와 용어가 다르고 업데이트 시 위치가 바뀐다.
- 기존 튜토리얼은 사용자가 설명을 읽고 현재 화면과 직접 비교해야 한다.
- 고령자는 막히는 순간 자녀에게 전화하거나 스크린샷을 보내는 경우가 많다.
- 자녀 입장에서는 반복 설명이 작은 시간 낭비와 감정적 마찰로 누적된다.
- 모든 조작을 AI에게 맡기면 보안과 책임 문제가 생기므로 “가이드”가 적절한 중간점이다.
# **3. 제품 사용 경험**
1. 사용자는 우리 앱을 설치하고 Accessibility 권한을 명시적으로 허용한다.
1. 카카오톡 등 지원 앱을 평소처럼 연다.
1. 화면의 작은 “도와줘” 버튼 또는 음성 진입점으로 원하는 일을 말한다.
1. 우리 서비스는 현재 앱의 UI 구조를 읽는다.
1. AI가 현재 화면에서 가장 적절한 다음 UI를 고른다.
1. 버튼 위에 테두리/번호/짧은 설명을 표시한다.
1. 사용자가 직접 버튼을 누른다.
1. 새 화면에서 다음 단계를 다시 안내하고 목적이 달성될 때까지 반복한다.

# **4. 하지 않는 것**

|**하지 않는 것**|**이유**|
| :- | :- |
|사용자 대신 무제한 자동 클릭|오조작·책임·Google Play 정책 리스크|
|금융 송금/결제 자동 수행|민감 거래는 최종 의사결정과 인증이 반드시 사용자에게 있어야 함|
|모든 앱 100% 지원 약속|앱별 접근성 구현과 보안 정책이 다름|
|상시 전체 화면 저장|프라이버시 리스크. 필요한 순간의 최소 UI 정보만 처리|
|고령자만 쓸 수 있는 복잡한 별도 앱|목표는 기존 앱 위에서 바로 도움을 주는 것|

# **5. MVP 범위**

|**추천 MVP**<br>Android 실기기 + 카카오톡 1개 앱 + 시나리오 2~3개 + 텍스트/음성 목표 입력 + Accessibility UI 읽기 + LLM 다음 노드 선택 + Overlay 하이라이트.|
| :- |

|**시나리오 후보**|**추천도**|**이유**|
| :- | :- | :- |
|채팅방 알림 끄기|높음|메뉴 전환이 명확하고 위험도가 낮음|
|차단 친구 해제|높음|여러 화면을 거치는 데모에 적합|
|프로필 사진 변경|중간|이미지 선택 등 UI 변수가 많을 수 있음|
|송금|낮음|금융/결제 관련 보안·책임 이슈. 해커톤 MVP에서 제외 추천|

# **6. 제품 철학**

|**UNWORK 문장**<br>사용법을 더 쉽게 가르치는 것이 아니라, 사용법을 알아내야 하는 일을 없앤다. AI에게 스마트폰을 맡기지 않고, 인터페이스를 이해하는 노동만 맡긴다.|
| :- |

# **7. 제품 이름/메시지 아이디어**
- “어디 눌러?”를 없애는 AI
- 모든 앱 위에 붙는 AI 사용성 레이어
- 앱을 배우지 않아도 되는 인터페이스
- Guide, not Autopilot — AI는 안내하고 사람은 결정한다.
# **8. 팀이 같은 그림을 갖기 위한 핵심 질문**
- 우리가 없애는 것은 클릭인가, 클릭할 위치를 알아내는 과정인가? → 후자.
- 사용자가 어떤 순간에 반드시 직접 결정해야 하는가? → 결제·송금·인증·삭제 등 되돌리기 어렵거나 민감한 행동.
- 어떤 앱부터 지원해야 하는가? → 접근성 정보가 비교적 잘 노출되고 위험도가 낮은 일반 생활 앱.
- AI가 틀렸을 때 어떻게 안전하게 실패할 것인가? → 낮은 확신이면 하이라이트하지 않고 질문/취소 제공.
- 제품 성공은 “AI가 많이 했다”가 아니라 “사용자가 헤매지 않았다”로 측정한다.
# **참고 자료**
**[S1] AI 스마트폰 도우미 - Google Play**\
https://play.google.com/store/apps/details?id=ai.fluiz.ditestbed\_agent\
2026-07-21 업데이트. 고령자 대상 접근성 앱으로, 음성 요청 후 Android Accessibility Service를 이용해 화면을 읽고 버튼 클릭·텍스트 입력·화면 이동을 수행한다고 설명.

**[S2] Gemini Live - Android Help**\
https://support.google.com/gemini/answer/15274899\
Android에서 화면 공유를 켜고 다른 앱을 사용하면서 Live 대화를 계속할 수 있음. 화면에 대한 실시간 도움을 제공.

**[S3] 손주도움 - Google Play**\
https://play.google.com/store/apps/details?id=com.guideops.app\
스마트폰 화면·키오스크·약봉투 등을 카메라로 비추면 다음 버튼과 사용법을 음성 안내.

**[S4] Android AccessibilityService API**\
https://developer.android.com/reference/android/accessibilityservice/AccessibilityService\
접근성 서비스는 UI 이벤트를 받고 활성 창의 UI 트리를 조회할 수 있으며 접근성 오버레이를 그릴 수 있음.

**[S5] Android AccessibilityNodeInfo API**\
https://developer.android.com/reference/android/view/accessibility/AccessibilityNodeInfo\
UI 노드의 text, contentDescription, boundsInScreen 등 접근성 정보를 조회할 수 있음.

**[S6] Google Play AccessibilityService 정책**\
https://support.google.com/googleplay/android-developer/answer/10964491?hl=ko\
접근성 API 사용 시 선언·공개·동의 요구. 일반 앱의 자율적 계획·실행 자동화는 제한되며 장애 지원이 핵심인 접근성 도구는 별도 기준 적용.

**[S7] Google Play 민감 권한/API 정책**\
https://support.google.com/googleplay/android-developer/answer/16558241\
Accessibility API는 보안 통제 우회·기만적 UI 조작 등에 사용할 수 없고 목적에 필요한 최소 데이터만 처리해야 함.
