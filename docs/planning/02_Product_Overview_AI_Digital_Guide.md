# 제품설명서 — 화면 Off 음성 자동실행 에이전트

팀원이 10분 안에 제품의 문제·경험·범위를 이해하기 위한 설명서

UNWORK Hackathon · 2026.08

# 1. 우리가 만드는 것은 무엇인가

| **제품 정의** 화면이 꺼진 상태에서 음성 한마디로 목적 앱을 실행시켜, 대화상대·사진 선택은 물론 전송까지 중단 없이 자동으로 완료하는 Android 음성 자동화 레이어다. |
| --- |

기존 사용자는 사진 한 장을 보내려면 화면을 켜고, 카카오톡을 찾고, 대화방을 찾아 들어가고, 첨부(+) → 앨범 → 사진 선택 → 전송을 하나씩 눌러야 한다. 각 단계의 아이콘이 무엇을 뜻하는지 알아야 하고, 이름이 비슷한 대화방 중 하나를 골라야 한다. 우리 제품은 이 조작 과정 전체와 전송 실행까지 AI가 대신한다. 사람이 하는 일은 처음 목적을 말하는 것과, AI가 정보가 부족해 되물을 때 답하는 것뿐이다.

[제품 개념] AI는 목적 발화부터 전송 완료까지 전 과정을 실행하고, 정보가 부족하면 그때그때 되물어 채운다.

# 2. 왜 필요한가

고령자는 앱 조작 자체가 부담스러워 자녀에게 사진 전송을 부탁하는 경우가 많다.

사진 보내기는 대화방 찾기 → 첨부 → 앨범 → 선택 → 전송까지 단계가 많고, 중간에 한 단계만 막혀도 흐름이 끊긴다.

연락처에 비슷한 이름이 여럿 있으면 대화방을 잘못 골라 엉뚱한 사람에게 보내게 된다.

자녀 입장에서는 반복적인 대리 전송과 반복 설명이 시간 부담으로 누적된다.

기존 튜토리얼·안내형 서비스는 사용자가 직접 화면을 조작해야 한다는 전제가 남아있다.

# 3. 제품 사용 경험

사용자는 우리 앱을 설치하고 Accessibility 권한과 화면 Off 음성 감지 권한을 명시적으로 허용한다.

화면이 꺼진 상태에서 wake word 뒤 원하는 일을 말한다. 이때 수신자나 어떤 사진인지를 다 말하지 않아도 된다 — 오히려 "사진 보내줘"처럼 짧게 말하는 경우가 기본이다.

서비스가 카카오톡 앱을 자동 실행한다.

AI가 현재 앱의 UI 구조를 읽고 대화방 진입 → 첨부 → 사진 선택까지 스스로 진행한다. 화면이 요구하는데 아직 말하지 않은 정보(누구에게, 어떤 사진)가 있으면 AI가 그때그때 음성으로 되묻고, 사용자의 답을 받아 이어서 진행한다.

이름이 비슷한 대화방 후보가 여럿이면 AI는 임의로 고르지 않고 후보를 읽어주며 되묻는다. 프롬프트에 "후보가 여럿이면 반드시 되물으라"는 규칙을 넣은 뒤 모호한 목표에서의 되묻기 성공률이 67% → 100%가 되었고, 목표가 명확할 때는 과잉 되묻기 없이 곧바로 실행한다.

수신자와 사진이 확정되면 전송 버튼까지 AI가 눌러 사진 전송을 완료한다.

[제품 플로우] 목적 발화 → (필요시 되묻기 반복) → 실제 전송 완료까지 자동 도달

# 4. 하지 않는 것

| **하지 않는 것** | **이유** |
| --- | --- |
| 정보가 불충분한 채로 임의 추측 진행 | 수신자·대상 사진이 확인되지 않으면 클릭 대신 되물어서 확인한다 |
| 이름이 비슷한 대화방 중 하나를 알아서 선택 | 전송은 되돌릴 수 없다. 부분 일치 후보가 2개 이상이면 반드시 사용자에게 확인받는다 |
| 모든 메신저 앱 100% 지원 약속 | 앱별 접근성 구현과 보안 정책이 다름 |
| 상시 전체 화면 저장 | 프라이버시 리스크. 대화방 화면에는 이전 대화 내용이 함께 노출되므로 필요한 순간의 최소 UI 정보만 처리하고 즉시 폐기 |
| 우리 backend/Android가 카카오 메시지 API를 직접 연동하는 별도 전송 구축 | 전송은 카카오톡 앱 자체의 전송 플로우를 accessibility로 그대로 자동 실행하며, 우리 시스템이 메시지 서버에 직접 연결되지는 않는다 |

# 5. MVP 범위

| **추천 MVP** Android 실기기 + 카카오톡 앱 + 사진 전송 시나리오 1개 + 화면 Off 음성 목표 입력 + 정보 부족 시 되묻기(ASK_USER) + Accessibility 기반 자동 진행 + 전송 자동 완료. |
| --- |

전송은 카카오톡 앱 자체의 실제 전송 화면을 accessibility로 자동 클릭해 완료한다. 우리 backend/Android가 카카오 메시지 API를 직접 호출하는 별도 연동을 구축하는 것은 이번 MVP 범위에서 제외한다(Out-of-Scope) — 전송은 어디까지나 카카오톡이 이미 갖고 있는 흐름을 그대로 자동 조작하는 방식이다.

| **시나리오 후보** | **추천도** | **이유** |
| --- | --- | --- |
| "엄마한테 사진 보내줘" | 높음 | 대표성 있고 대화상대·사진·전송 흐름이 명확함 |
| "사진 보내줘" (수신자·사진 미지정) | 높음 | 되묻기(ASK_USER) 흐름을 그대로 보여줄 수 있는 핵심 데모 |
| 자주 보내는 상대에게 반복 전송 | 중간 | 사용자별 자주 쓰는 대화상대 학습 여지 있음 |
| 여러 장 묶어 보내기 / 앨범 전체 전송 | 낮음 | 잘못 보냈을 때 피해 범위가 커지고 선택 UI가 복잡함, 해커톤 MVP에서 제외 추천 |

# 6. 제품 철학

| **UNWORK 문장** 사진 보내는 법을 더 쉽게 가르치는 것이 아니라, 사진을 보내기 위해 화면을 켜고 앱을 조작해야 하는 일 자체를 없앤다. AI에게 맡길 것은 조작과 전송 실행이고, 사람에게 남길 것은 처음 목적을 말하는 것과 AI가 되물을 때 답하는 것뿐이다. |
| --- |

# 7. 제품 이름/메시지 아이디어

"화면을 켤 필요가 없는 사진 전송"

말 한마디로 전송까지 끝내는 AI

앱을 조작하지 않아도 되는 메신저

Wake, then Sent — 깨우면, AI가 보내 놓는다.

# 8. 팀이 같은 그림을 갖기 위한 핵심 질문

우리가 없애는 것은 조작인가, 조작에 대한 판단인가? → 둘 다. 전송 실행까지 AI가 대신한다.

사용자가 어떤 순간에 반드시 직접 개입해야 하는가? → AI가 정보 부족으로 되물을 때(누구에게 / 어떤 사진), 그리고 이름이 비슷한 대화방 후보가 여럿일 때다.

> (팀 확인 필요) 마지막 전송 버튼 직전에도 사용자 확인을 한 번 받을 것인지는 아직 미정. 전송은 취소가 불가능하다는 점과, 확인 단계가 늘면 "조작 노동 제거"라는 핵심 가치가 희석된다는 점을 함께 놓고 결정해야 한다.

어떤 상황부터 지원해야 하는가? → 접근성 정보가 잘 노출되고, 수신자를 텍스트로 식별할 수 있는 대화방 진입 시나리오.

AI가 틀렸을 때 어떻게 안전하게 실패할 것인가? → 낮은 확신이면 클릭을 강행하지 않고 진행을 멈춰 사용자에게 되물어 확인한다. 잘못 전송된 사진은 회수할 수 없고 사생활 침해가 될 수 있으므로 confidence 임계값을 보수적으로 운영한다.

**[S4] Android AccessibilityService API**
https://developer.android.com/reference/android/accessibilityservice/AccessibilityService
접근성 서비스는 UI 이벤트를 받고 활성 창의 UI 트리를 조회할 수 있으며 접근성 오버레이를 그릴 수 있음.

https://developer.android.com/reference/android/view/accessibility/AccessibilityNodeInfo

**[S6] Google Play AccessibilityService 정책**
https://support.google.com/googleplay/android-developer/answer/10964491?hl=ko

**[S7] Google Play 민감 권한/API 정책**
https://support.google.com/googleplay/android-developer/answer/16558241
Accessibility API는 보안 통제 우회·기만적 UI 조작 등에 사용할 수 없고 목적에 필요한 최소 데이터만 처리해야 함.
