# **3. B2C 모델**

|**플랜**|**예시 기능**|**가격 가설**|
| :- | :- | :- |
|Free|월 제한된 AI 가이드, 기본 텍스트 안내|무료|
|Family|무제한 가이드, 음성, 가족 도움 요청 기록, 지원 앱 확대|월 4,900~9,900원 가설|
|Care+|보호자 대시보드, 자주 막히는 기능 분석, 우선 지원|월 9,900~14,900원 가설|

가격은 검증되지 않은 가설이다. 초기 해커톤에서는 과금보다 “부모/자녀가 실제로 이 문제를 돈 내고 해결할 의사가 있는지”를 인터뷰로 확인해야 한다.
# **4. B2B2C 모델**
- 통신사: 시니어 요금제·디지털 케어 서비스에 번들.
- 은행/핀테크: 고객이 자사 앱에서 메뉴를 찾지 못해 콜센터에 문의하는 빈도를 줄이는 접근성 기능. 민감 거래는 사용자 직접 실행.
- 공공기관: 정부·복지·교통 앱의 디지털 취약계층 사용성 보조.
- 병원/보험: 예약·서류·조회 절차에서 길찾기형 UI 가이드.
- 스마트폰 제조사: 시니어 모드/접근성 기능에 통합.
# **5. SDK/API 모델**
장기적으로는 외부 앱 사업자가 자체 앱의 UI 구조/목표 경로를 제공하면 우리 엔진이 사용자에게 가이드하는 SDK 형태가 가능하다. 앱 사업자 입장에서는 FAQ·튜토리얼을 반복 제작하는 대신 사용자의 실제 화면에서 상황 맞춤 안내를 제공할 수 있다.

|**수익원**|**과금 단위 예시**|
| :- | :- |
|B2C 구독|사용자/가족 단위 월 구독|
|B2B 라이선스|기관당 월/연 계약|
|MAU 기반 SDK|월 활성 사용자 또는 가이드 세션 수|
|화이트라벨|기관 브랜드로 제공하는 구축·운영비|
|프리미엄 지원 앱 팩|특정 공공/생활 앱에 대한 고품질 경로 패키지|

# **6. 비용 구조**
- LLM/Vision inference 비용: UI Tree만으로 판단 가능한 경우 최소화.
- Android 앱 개발 및 QA: OS 버전·제조사·지원 앱별 테스트 비용.
- 보안/개인정보: 데이터 최소화, 감사, 정책 대응.
- 지원 앱 유지보수: 앱 업데이트로 메뉴가 바뀌었을 때 정확도 모니터링.
- 고객지원/온보딩: Accessibility 권한을 이해시키는 교육 비용.
# **7. 시장 진입 전략**
1. 카카오톡 등 익숙한 앱 1개에서 실사용 테스트로 “다음 단계 정확도”와 만족도를 검증.
1. 부모-자녀 5~10쌍을 대상으로 실제 반복 질문이 얼마나 줄어드는지 관찰.
1. 공공·교통 앱처럼 사회적 가치가 크고 결제 위험이 낮은 영역으로 확장.
1. 기관 PoC: 디지털 배움터, 복지관, 통신사 시니어 고객센터 등과 사용성 테스트.
1. 정확도와 안전성이 확보된 후 SDK/기관 계약 모델로 확대.
# **8. BM의 가장 큰 리스크**

|**리스크**|**영향**|**검증 방법**|
| :- | :- | :- |
|사용자가 Accessibility 권한을 꺼림|온보딩 이탈|5명 이상 실제 설치 테스트|
|무료 Gemini 등으로 충분|B2C 지불 의사 낮음|우리 overlay 가이드가 대화형 도움보다 실제 완료율을 개선하는지 A/B|
|앱 업데이트 대응 비용|운영비 증가|UI Tree 기반 범용성 측정|
|기관 도입의 보안 우려|B2B 판매 지연|로컬 처리/민감 노드 마스킹 설계|
|고령자가 음성 진입 자체를 어려워함|제품 사용 실패|큰 floating button, 자녀가 초기 설정 지원|

Android에서 화면 공유를 켜고 다른 앱을 사용하면서 Live 대화를 계속할 수 있음. 화면에 대한 실시간 도움을 제공.

**[S3] 손주도움 - Google Play**\
https://play.google.com/store/apps/details?id=com.guideops.app\
스마트폰 화면·키오스크·약봉투 등을 카메라로 비추면 다음 버튼과 사용법을 음성 안내.

**[S4] Android AccessibilityService API**\
https://developer.android.com/reference/android/accessibilityservice/AccessibilityService\
접근성 서비스는 UI 이벤트를 받고 활성 창의 UI 트리를 조회할 수 있으며 접근성 오버레이를 그릴 수 있음.

**[S5] Android AccessibilityNodeInfo API**\
https://developer.android.com/reference/android/view/accessibility/AccessibilityNodeInfo\
UI 노드의 text, contentDescription, boundsInScreen 등 접근성 정보를 조회할 수 있음.

**[S6] Google Play AccessibilityService 정책**\
https://support.google.com/googleplay/android-developer/answer/10964491?hl=ko\
접근성 API 사용 시 선언·공개·동의 요구. 일반 앱의 자율적 계획·실행 자동화는 제한되며 장애 지원이 핵심인 접근성 도구는 별도 기준 적용.

**[S7] Google Play 민감 권한/API 정책**\
https://support.google.com/googleplay/android-developer/answer/16558241\
Accessibility API는 보안 통제 우회·기만적 UI 조작 등에 사용할 수 없고 목적에 필요한 최소 데이터만 처리해야 함.
