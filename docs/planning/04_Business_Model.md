# 비즈니스 모델 — 화면 Off 음성 자동예매 에이전트

해커톤 이후 실제 서비스로 확장할 경우의 고객, 과금, 파트너십 가설

UNWORK Hackathon · 2026.08

# 1. BM 한 줄 요약

| **BM 방향** 초기에는 B2C로 문제와 사용성을 검증하고, 장기적으로는 철도·항공 등 예매 플랫폼 사업자가 자사 앱에 공식 SDK로 결합하는 B2B2C 모델이 정책·법적 리스크를 낮추는 더 안정적인 확장 경로다. |
| --- |

[도식] B2C 검증(비공식 자동화) → B2B2C 공식 SDK 결합 → 예매 플랫폼 공식 파트너십

# 2. 고객과 사용자 구분

| **구분** | **누구** | **가치** |
| --- | --- | --- |
| 직접 사용자 | 예매 경쟁이 치열한 시간대 이용자, 고령자·디지털 취약 사용자 | 조작 없이 결제 직전까지 자동 도달 |
| 가족 구매자 | 자녀·보호자 | 대리 예매 시간 감소 |
| 기관 고객 | 철도·항공 등 예매 플랫폼 사업자 | 비공식 매크로 탐지 부담 대신 공식 자동화 채널 확보 |
| 앱 사업자 | 자사 예매 앱 운영 기업 | 공식 SDK로 우회 자동화 리스크를 통제 가능한 채널로 흡수 |

# 3. B2C 모델

| **플랜** | **예시 기능** | **가격 가설** |
| --- | --- | --- |
| Free | 월 제한된 자동예매, 기본 텍스트/음성 안내 | 무료 |
| Family | 무제한 자동예매, 가족 예매 기록 공유, 지원 앱 확대 | 월 4,900~9,900원 가설 |
| Priority | 예매 경쟁 시간대 우선 처리, 선호 좌석 학습, 우선 지원 | 월 9,900~14,900원 가설 |

가격은 검증되지 않은 가설이다. 초기 해커톤에서는 과금보다 "화면 Off 자동예매에 실제로 돈을 낼 의사가 있는지"를 인터뷰로 확인해야 한다.

# 4. B2B2C 모델

철도/항공사: 비공식 매크로 자동화로 인한 서버 부담·부정거래 문제를 공식 SDK 제휴로 흡수.

통신사: 시니어 요금제·디지털 케어 서비스에 번들.

공공기관: 디지털 취약계층의 예매 접근성 지원.

스마트폰 제조사: 음성 비서 상시 대기 기능에 통합.

# 5. SDK/API 모델

장기적으로는 예매 플랫폼 사업자가 공식 API를 제공하면 매크로 탐지 리스크 없이 동일한 자동 진행 경험을 SDK 형태로 제공할 수 있다.

| **수익원** | **과금 단위 예시** |
| --- | --- |
| B2C 구독 | 사용자/가족 단위 월 구독 |
| B2B 라이선스 | 예매 플랫폼당 월/연 계약 |
| 공식 API 연동 SDK | 월 활성 사용자 또는 자동예매 세션 수 |
| 화이트라벨 | 플랫폼 브랜드로 제공하는 구축·운영비 |

# 6. 비용 구조

LLM/Vision inference 비용: UI Tree만으로 판단 가능한 경우 최소화.

Android 앱 개발 및 QA: OS 버전·제조사·지원 앱별 테스트 비용.

매크로 탐지 우회 대응 비용: 비공식 자동화 상태에서 발생하는 모니터링·정책 대응 비용.

보안/개인정보: 데이터 최소화, 감사, 정책 대응.

고객지원/온보딩: Accessibility 권한 및 자동예매 범위를 이해시키는 교육 비용.

# 7. 시장 진입 전략

해커톤 데모는 목업 환경을 우선 사용하고 실 서버는 최소 검증만 진행.

부모-자녀 5~10쌍을 대상으로 대리 예매 시간이 얼마나 줄어드는지 관찰.

공식 파트너십 없이 실 서비스로 확장할 경우 정책/법적 리스크가 크므로, 장기적으로는 반드시 예매 플랫폼과의 공식 제휴 경로를 병행 추진.

정확도와 결제 게이트 신뢰가 확보된 후 SDK/기관 계약 모델로 확대.

# 8. BM의 가장 큰 리스크

| **리스크** | **영향** | **검증 방법** |
| --- | --- | --- |
| 비공식 자동화로 인한 계정 정지/법적 분쟁 | 서비스 중단 리스크 | 목업 검증 우선, 공식 파트너십 전환 로드맵 수립 |
| 사용자가 결제 자동화 신뢰 안 함 | B2C 채택 저하 | 결제 대기 화면 UX A/B 테스트 |
| 예매 플랫폼의 매크로 탐지 강화 | 정확도/성공률 하락 | 탐지 패턴 회피가 아닌 공식 API 확보로 근본 해결 |
| 앱 업데이트 대응 비용 | 운영비 증가 | UI Tree 기반 범용성 측정 |
| 고령자가 음성 진입 자체를 어려워함 | 제품 사용 실패 | 큰 floating button 병행, 자녀가 초기 설정 지원 |

# 9. 해커톤에서 BM 발표 범위

| **추천** 해커톤에서는 실 서비스 상용화를 강하게 주장하기보다, "화면 Off 음성 진입 + 결제 게이트" UX 검증과, 장기적으로 예매 플랫폼과의 공식 파트너십이 필요하다는 점을 함께 제시하는 것이 설득력이 높다. |

**[S4] Android AccessibilityService API**
https://developer.android.com/reference/android/accessibilityservice/AccessibilityService
접근성 서비스는 UI 이벤트를 받고 활성 창의 UI 트리를 조회할 수 있으며 접근성 오버레이를 그릴 수 있음.

**[S5] Android AccessibilityNodeInfo API**
https://developer.android.com/reference/android/view/accessibility/AccessibilityNodeInfo
UI 노드의 text, contentDescription, boundsInScreen 등 접근성 정보를 조회할 수 있음.

**[S6] Google Play AccessibilityService 정책**
https://support.google.com/googleplay/android-developer/answer/10964491?hl=ko
접근성 API 사용 시 선언·공개·동의 요구. 일반 앱의 자율적 계획·실행 자동화는 제한되며 장애 지원이 핵심인 접근성 도구는 별도 기준 적용.

**[S7] Google Play 민감 권한/API 정책**
https://support.google.com/googleplay/android-developer/answer/16558241
Accessibility API는 보안 통제 우회·기만적 UI 조작 등에 사용할 수 없고 목적에 필요한 최소 데이터만 처리해야 함.

**[S8] 코레일 매크로 승차권 불법거래 대응 관련 보도**
매크로 프로그램을 이용한 승차권 부당 확보·재판매는 철도사업법상 단속 대상이며, 코레일은 빅데이터 기반 모니터링과 매크로 탐지 솔루션으로 비정상 접속을 실시간 차단하고 있다고 보도됨.

**[S9] 코레일 매크로 탐지 솔루션 운영 관련 보도**
설·추석 등 예매 성수기에 매크로 탐지 솔루션을 가동해 비정상적 접속 시도 수만 건을 차단한 사례가 보도됨.
